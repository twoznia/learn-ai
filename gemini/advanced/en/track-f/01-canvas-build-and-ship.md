## 🧠 Theory (4 min)

Track A3 introduced **Canvas** for documents. Here we push it further: Canvas can build **working, interactive things** — a small web app, a calculator, a quiz, code you preview and run — right in the side panel, and you can **share** the result.

Instead of scrolling a chat for the "final version," you **iterate on a living object** and end with something you can use or send.

What Canvas can build:
- **Interactive web apps** — a tool, a calculator, a mini-game (Gemini writes real HTML/JS and previews it).
- **Code** — a script or component you can run and refine.
- **Documents** — reports and guides you keep editing (the A3 use).

---

## 🛠️ Practice (10 min)

### Step 1 — Build an interactive app

In the Gemini app, open Canvas and ask for something you can use:

```text
In Canvas, build a small "tip calculator" web page: bill amount, tip %, number
of people, showing tip and total per person. Make it clean, and preview it.
```

Canvas builds a working page you can **actually use** in the preview — type numbers and watch it compute.

### Step 2 — Iterate on the living object

Refine in place — don't start over:

```text
Add a dark mode toggle and round the per-person total to the nearest cent.
```

Canvas edits the **same** object. You're shaping one thing, not collecting drafts.

### Step 3 — Try code you can run

```text
In Canvas, write a Python function that takes a list of numbers and returns
the mean, median, and max. Include a quick example run.
```

You get code you can read, run, and tweak by asking for changes.

### Step 4 — Preview, test, refine loop

Use Canvas the way a builder does:
- Preview → find something off → describe the fix → preview again.

```text
The button is hard to see on mobile. Make it full-width and larger on small screens.
```

Each request edits the artifact; you never hand-edit.

### Step 5 — Share it

When it's ready, use Canvas's **share/export** option to send it or drop it into Google Docs. You share the **result**, not your chat.

> ⚠️ **Before you share:** review for private data. Don't publish anything with credentials or content that impersonates a real person or organization.

### Step 6 — Know the good use cases

Reach for Canvas when the output is something you'll **keep, run, edit, or hand to someone**: an app, a script, a doc. For a quick one-off answer, plain chat is fine.

## 🧩 When to use Canvas

| Want… | Canvas? |
|-------|---------|
| A working tool/app you'll use | ✅ Yes |
| Code you'll run and refine | ✅ Yes |
| A document you'll keep editing | ✅ Yes |
| A quick factual answer | ❌ Plain chat |
| Something to share/export | ✅ Yes (review first) |

- [ ] You produced runnable code in Canvas.

## 🎯 Homework

Build one Canvas artifact you'd genuinely use — a personal calculator, a small tool, or a script. Iterate it three times with follow-up requests, then share or export it.

---

## 💡 Key takeaways

- **Canvas** builds **interactive apps, runnable code, and documents** in a side panel — not just text.
- **Iterate in place** with follow-up requests; use the preview → fix → preview loop.
- **Share/export** the result (into Docs or a link) — review for privacy first.
